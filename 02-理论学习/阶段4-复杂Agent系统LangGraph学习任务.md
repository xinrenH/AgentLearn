## 学习前必读：为什么需要 LangGraph？

**简单 Agent 的问题**：用户→Agent 调工具→返回答案。一条直线，没有分支、没有循环、没有记忆。

**真实世界的 Agent 需要**：
```
用户: "帮我写一份本周工作总结"
  ↓
步骤1: 获取本周所有任务记录（查数据库）
  ↓
步骤2: 按项目分类整理（LLM 分类）
  ↓
步骤3: 生成总结草稿（LLM 生成）
  ↓
步骤4: 自查草稿质量（LLM 自我评估）→ 不合格？回到步骤3重写
  ↓
步骤5: 格式化为 Markdown → 输出给用户
```

这就是**状态图（StateGraph）**——有节点（步骤）、有边（流转）、有条件分支、有循环。

**LangGraph 是 LangChain 生态的状态图编排引擎**，专门用来构建这种复杂的多步骤 Agent。

## 学习任务 1：LangGraph 基础 — 状态图入门

### 任务目标
理解状态图（StateGraph）的概念，能搭一个简单的多节点流水线。

### 核心概念
- **State**：一个 TypedDict，在整个图执行过程中流转，每个节点都能读写它
- **Node**：一个处理函数，接收 State，返回 State 的部分更新
- **Edge**：节点之间的普通连接（A 一定到 B）
- **Conditional Edge**：条件分支（A 根据状态决定到 B 还是 C）
- **Compile**：把节点和边"编译"成可执行的应用

### 实战练习

| # | 练习 | 具体要求 |
|---|------|---------|
| 1.1 | 安装 LangGraph | `pip install langgraph langchain langchain-openai` |
| 1.2 | 第一个 StateGraph | 建 3 个节点：`add_prefix`（加前缀）→ `translate`（翻译）→ `add_suffix`（加后缀）。State 在节点间流转 |
| 1.3 | 条件分支 | 加入第 4 个节点 `router`：根据 State 中的 `language` 字段决定走"中文输出"还是"英文输出"分支 |
| 1.4 | 循环 | 实现"翻译+审校"循环：翻译 → 审校（LLM 评估质量）→ 不合格？回到翻译节点重来 → 合格则输出 |
| 1.5 | 可视化 | 用 `graph.get_graph().draw_mermaid_png()` 生成流程图，确认你对图结构的理解与代码一致 |

### 产出物
- `langgraph_basics.py` — 一个含条件分支和循环的状态图
- 一张 Mermaid 流程图 PNG

### 验收标准
- 能解释 StateGraph 的 5 个核心概念
- 能画出自己的图结构并确认与代码一致
- 能实现含条件分支和简单循环的流水线

## 学习任务 2：多步骤任务 Agent

### 任务目标
用 LangGraph 实现一个能自动分解并执行多步骤任务的 Agent。

### 学习内容
- **Plan-Act-Reflect 循环**：规划 → 执行 → 反思 → 修正 → 再执行 → 直到完成
- 任务分解：LLM 把复杂任务拆成子步骤
- 执行步骤控制：当前做到哪一步了、下一步做什么
- 终止条件判断：什么情况下任务算是"完成了"

### 实战练习

| # | 练习 | 具体要求 |
|---|------|---------|
| 2.1 | 任务分解 | 实现 `planner` 节点：用户给一个复杂任务（如"分析 XX 公司的财报"），LLM 拆成 3-5 个子步骤 |
| 2.2 | 步骤执行 | 实现 `executor` 节点：逐个执行子步骤（调用搜索、计算、总结等工具） |
| 2.3 | 结果评估 | 实现 `evaluator` 节点：检查当前步骤结果是否满足要求。不满足 → 回到 executor 重做 |
| 2.4 | 进度追踪 | State 中维护 `completed_steps` 和 `current_step`，每次循环更新。可视化当前进度 |
| 2.5 | 失败回退 | 某步骤执行 3 次仍失败 → 标记失败 → 跳过该步骤 → 继续下一步（不阻塞整个任务） |

### 产出物
- `task_agent.py` — 完整的 Plan-Act-Reflect Agent
- 执行轨迹日志（每步的时间、输入、输出、评估结果）

### 验收标准
- Agent 能自动分解复杂任务并逐步执行
- 中间步骤失败能重试或跳过
- 执行过程完整可追踪

## 学习任务 3：Agent 记忆系统

### 任务目标
给 Agent 加上"记忆"——能记住之前的对话、用户偏好、任务历史。

### 学习内容
- **短期记忆（Short-term Memory）**：当前对话的上下文窗口
- **长期记忆（Long-term Memory）**：跨会话持久化存储（用户偏好、历史任务）
- 记忆的存储、检索、更新、遗忘（过期）策略
- 记忆嵌入检索：用语义相似度召回相关历史记忆
- 记忆摘要：历史对话太长时压缩成摘要

### 实战练习

| # | 练习 | 具体要求 |
|---|------|---------|
| 3.1 | 对话历史管理 | 实现一个消息管理器：存储对话历史（JSON 文件），新对话时加载上一次的历史 |
| 3.2 | 会话摘要 | 当对话历史超过 token 限制时，用 LLM 压缩成摘要（保留关键信息），旧消息清掉只保留摘要 |
| 3.3 | 用户偏好记忆 | 自动提取用户在对话中透露的偏好（如"我喜欢简洁的回答""我是后端开发"），存入长期记忆库 |
| 3.4 | 记忆检索 | 每次新对话开始时，用当前问题做语义搜索，召回相关的历史记忆，拼入 system prompt |
| 3.5 | 记忆更新与遗忘 | 30 天未访问的记忆自动标记为"过期"。用户说"我不需要 XXX 了"时主动删除相关记忆 |

### 产出物
- `memory_system.py` — 含短期/长期记忆管理的记忆系统
- 一个记忆存储结构（JSON 文件 + ChromaDB 做语义搜索）
- 多轮对话测试：Agent 能记住之前提到的信息

### 验收标准
- 连续对话中 Agent 能记住历史关键信息
- 对话历史过长时自动压缩为摘要
- 用户偏好能跨会话保持
- 过旧的记忆自动清理

## 学习任务 4：Human-in-the-Loop（人机协同）

### 任务目标
实现关键操作的人类审批机制——Agent 不能无限制自主操作。

### 学习内容
- LangGraph 的 `interrupt_before` / `interrupt_after` 机制
- 哪些操作需要人类确认：发邮件、删数据、发消息、付款
- 审批通过 / 拒绝 / 修改的交互流程
- 超时自动拒绝

### 实战练习

| # | 练习 | 具体要求 |
|---|------|---------|
| 4.1 | 拦截关键操作 | 在 LangGraph 中用 `interrupt_before=["send_email", "delete_record"]` 拦截关键节点 |
| 4.2 | 审批交互 | 拦截后暂停 → 向用户展示"Agent 将要执行 XXX，是否同意？(y/n/修改参数)"→ 用户输入后继续或中止 |
| 4.3 | 超时撤销 | 拦截后等待 60 秒，超时无响应则自动拒绝并回滚 |
| 4.4 | 审批日志 | 所有审批记录（时间、操作、Agent 理由、用户决策）写入审计日志 |

### 产出物
- `human_in_the_loop.py` — 含审批机制的 Agent
- 审计日志文件

### 验收标准
- 关键操作被自动拦截并等待人类确认
- 超时自动拒绝
- 所有审批有日志可查

## 学习任务 5：错误恢复与自我修复

### 任务目标
Agent 在执行过程中遇到错误（工具故障、LLM 返回异常、超时）能自动恢复。

### 学习内容
- 节点级别的 try/except 包裹
- 图级别的全局错误处理
- 错误分类：可重试的（网络超时）、不可重试的（参数错误）、需人工介入的
- 降级路径：错误发生时走备选方案

### 实战练习

| # | 练习 | 具体要求 |
|---|------|---------|
| 5.1 | 节点异常处理 | 每个 LangGraph 节点用 try/except 包裹，异常时记录到 State 的 `errors` 字段 |
| 5.2 | 错误路由 | 根据错误类型走不同路线：网络错误 → 重试节点；参数错误 → 向 LLM 反馈修正；未知错误 → 终止并通知用户 |
| 5.3 | 部分成功处理 | 5 个步骤的任务中第 3 步失败 → 前 2 步的结果不丢弃 → 用户可以选择"用前 2 步结果 + 跳过第 3 步" |
| 5.4 | 自动修复 | 某些常见错误（如缺少某个字段）LLM 能自动检查 State 并补充。实现 `auto_fix` 节点 |

### 产出物
- `error_recovery.py` — 含完整错误处理的状态图
- 错误分类表和对应的处理策略

### 验收标准
- Agent 执行途中出错不会崩溃
- 能根据错误类型自动选择重试、降级或终止
- 错误和恢复过程记录在日志中

## 学习任务 6：综合实战 — 智能周报生成 Agent

### 任务目标
综合 LangGraph、记忆系统、多步骤规划、Human-in-the-loop，做一个真正有用的"周报生成 Agent"。

### 功能需求

```
智能周报生成 Agent
==================
完整流程：
1. 数据采集
   - 从任务管理工具/数据库获取本周所有任务
   - 从 Git 获取本周代码提交记录
   - 从对话记录获取本周会议纪要

2. 智能分析
   - LLM 对任务进行分类（开发/测试/文档/会议/其他）
   - 识别本周关键成果和亮点
   - 识别未完成项和阻塞项

3. 摘要生成
   - LLM 生成 3 段式周报：
     ① 本周完成（含具体数据和成果）
     ② 遇到的问题与处理
     ③ 下周计划

4. 质量审查
   - Agent 自查周报质量（完整性、数据准确性）
   - 不满足要求 → 回到步骤 3 重写（最多 2 次）

5. 人工审核（Human-in-the-loop）
   - 展示周报草稿
   - 用户可：确认发布 / 修改某段 / 退回重写
   - 确认后保存为 Markdown 文件

6. 记忆更新
   - 将本周的关键成果存入长期记忆
   - 下次生成周报时可引用历史成果做对比
```

### 状态图设计

```
                    ┌──────────┐
                    │  START   │
                    └────┬─────┘
                         ↓
                   ┌──────────┐
                   │ 采集数据  │ ← 从各个数据源拉数据
                   └────┬─────┘
                         ↓
                   ┌──────────┐
                   │ 智能分析  │ ← 分类、提取亮点
                   └────┬─────┘
                         ↓
              ┌──────────────────┐
              │   周报生成        │ ← LLM 写初稿
              └────┬─────────────┘
                   ↓
              ┌──────────┐   不合格
              │ 质量审查  │────────┐
              └────┬─────┘        │
                   │ 合格          │
                   ↓              │
              ┌──────────┐        │
              │ 人工审核  │        │
              └────┬─────┘        │
                   │              │
        ┌──────────┼────────┐     │
        ↓          ↓        ↓     │
    [确认发布] [修改某段] [退回重写]─┘
        ↓          ↓
   ┌────────┐  ┌───────┐
   │保存文件│  │修改内容│→ 回到审核
   └────┬───┘  └───────┘
        ↓
   ┌────────┐
   │更新记忆│
   └────┬───┘
        ↓
   ┌────────┐
   │  END   │
   └────────┘
```

### 技术要求
- LangGraph 实现完整状态图
- 不少于 6 个节点（采集、分析、生成、审查、审核、记忆更新）
- 至少 2 处条件分支
- Human-in-the-loop 审批节点
- 完善的错误处理和日志
- 记忆系统（JSON + ChromaDB）

### 产出物
- `weekly_report_agent/` 项目目录：
  - `main.py` — 入口
  - `graph.py` — LangGraph 状态图定义
  - `nodes/` — 各节点实现（collector、analyzer、generator、reviewer、approver、memory）
  - `state.py` — State 定义
  - `tools/` — 工具函数（数据库查询、Git 查询等）
  - `memory/` — 记忆系统
  - `data/` — 模拟数据（测试用）
- `README.md` — 架构说明、流程图、使用方法
- 生成的真实周报样例（Markdown）

### 验收标准
- 输入"生成本周周报"，Agent 自动完成 6 步流程
- 周报内容包含具体数据而非空话
- 质量不达标时自动重写
- 人工审核环节正常拦截
- 生成的周报可保存为 Markdown 文件
- 执行全过程有轨迹日志
